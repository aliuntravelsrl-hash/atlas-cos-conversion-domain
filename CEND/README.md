# CEND — Joint Domain Entry

CEND conjunta del dominio CONVERSION.

Esta entrada no reabre arqueología. El dominio ya posee una ruta persistida. Cada involucrado entra sobre la misma representación y aporta su propia perspectiva al mismo estado de la pelota.

## Participantes

- **Director / CCAMEL 360** — autoridad soberana y visión/reconciliación 360.
- **ATLAS SALES** — estructura y mecanismos comerciales.
- **HERMES COMMERCIAL** — ejecución comercial gobernada.
- **ATLAS SALES MCP** — infraestructura de herramientas/capabilities para la ejecución.
- **CONVERSION DOMAIN** — plano de navegación, sincronización, evidencia, aprendizaje y genealogía.

## Regla de entrada

Cada participante debe verificar:

```text
IDENTIDAD
  ↓
ESTADO ACTUAL
  ↓
RUTA PERSISTIDA
  ↓
PELOTA ACTUAL
  ↓
EVIDENCIA DISPONIBLE
  ↓
SIGUIENTE ACCIÓN / OBSERVACIÓN
```

No se presume continuidad por memoria conversacional. La continuidad proviene de la representación persistida y de la evidencia actual.

## Regla de sincronización

Los participantes no tienen que compartir implementación. Deben sincronizar el contexto requerido para que la pelota avance sin perder estado, evidencia o trazabilidad.

## Resultado de CEND

CEND termina cuando existe una posición común verificable:

- dónde está la pelota;
- qué comportamiento corresponde al siguiente punto;
- qué evidencia ya existe;
- qué debe observarse a continuación;
- qué DELTAS ya están registrados;
- qué queda fuera de esta fase.

CEND no resuelve GAP / EVO. Prepara navegación segura para continuar el Drill.
